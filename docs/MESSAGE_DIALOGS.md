# System message dialog dismissal

The port's headless system-dialog adapter automatically answers confirmation dialogs. For a no-button notice whose type permits cancellation, automatic dismissal now returns `CELL_MSGDIALOG_BUTTON_ESCAPE` (3). This represents the user cancel action. Returning `CELL_MSGDIALOG_BUTTON_NONE` (-1) represents the title closing its own notice, and is retained for explicit `cellMsgDialogClose()` and for automatic dismissal when cancellation is disabled. Progress notices still wait for title Close/Abort; Abort does not queue a completion. The optional no-button grace-period path uses the same cancellation rule when its timer simulates user dismissal.

This distinction fixes the disconnect-dialog loop. Tank Battles opens the room-disconnected notice with type `0x03`, without buttons and with cancellation enabled. Its callback at `func_001D69DC` maps NONE to internal result4 and ESCAPE to result3. With NONE, an invited peer can stay in the old game scene and then loop in Loading when leaving. In a paired three-player test with original pacing on every peer, the unchanged invitee remained in that state while the invitee receiving ESCAPE returned to the main menu after the same host departure. The issue therefore also occurs with the online FPS correction disabled.

The maintained fix is an exact SDK overlay in `scripts/instrument_sdk.py`; vendored SDK source and generated title code are unchanged. It selects behavior from the dialog flags, without matching English message text. `scripts/test_message_dialog.py` compiles the actual overlay and verifies cancellable/cancel-disabled notices, OK/Yes confirmations, progress Close/Abort and grace-period dismissal. The existing deferred guest callback queue remains responsible for delivery on a sysutil poll.
